# ADR 0013: Bounded opt-in transition observation

Status: accepted implementation contract for M15. See the task graph for implementation verification.
Date: 2026-11-17. The accepted compiler core is unchanged at `127fba1`.

## Decision

Transition tracing records actual executed events. A static plan, generated C
listing, or replayed source evaluation cannot stand in for that record.
Tracing is opt-in, with a separate sink from program stdout and diagnostics.
The untraced API and default execution behavior stay available.

Use a caller-owned bounded record store. Capture never allocates, invokes
user callbacks, or performs file I/O. It copies only bounded previews and
numeric IDs. Once capacity is exhausted, later events are omitted; an explicit
truncation flag and saturating omission count make incompleteness visible.
Recording failure must not replace a language outcome, consume interpreter
step budgets, or reorder candidate/guard/emission work. Formatting and sink
errors are reported separately by the host after execution, and cannot publish
program output from a failed transition.

Records are meaningful only alongside their exact verified Core source
metadata. No pointers, closure internals, allocation addresses, or host object
identities belong in persisted traces. Text previews retain counted bytes
(including NUL); formatting must escape them without accidental truncation.
Aggregate previews have explicit depth/work/byte bounds and an indication of
omitted content. A preview is an explanation, never a serialized mutable value.

## Event schema version 1

Each record has a monotonically increasing sequence number, a dynamic
invocation ID, parent invocation ID, event kind, function/span ID, and an
ordinal identifying its source machine cell, guard, or emission when
applicable. ID zero means absent. The originating verified Core identifies the
module, nominal machine, cell names and original source span.

The intended ordered event families are:

1. `step_begin`: invocation metadata and bounded old-snapshot/input preview.
2. `writer`: a completed scheduled candidate and its bounded preview.
3. `guard`: a completed guard Boolean, in source order.
4. `emission`: a computed private emission, after every guard succeeds.
5. `accept`: all emitted values and accepted snapshot are complete.
6. `reject`: the first false guard's reason is complete; old snapshot retained.
7. `fault`: a language fault aborts the invocation; nothing is published.

Failed writer expressions have no completed writer record. A faulting guard
has no completed guard record. A false guard whose rejection expression
faults produces a guard record followed by fault, without reject. Previously
computed emissions may appear in a faulted trace, clearly labeled private;
their presence is not publication. Truncation may omit a terminal event.
Replay inspection must flag that the terminal outcome is unknown.

Nested step calls receive fresh invocation IDs and identify their active
parent. Ordinary function calls do not create machine invocations. The dynamic
ID counter saturates by disabling capture and marking truncation, never by
wrapping or failing the program. Snapshot previews are copied during capture;
no trace record extends a VM or reference-counted runtime object's lifetime.

## Integration boundary

Core remains ordinary typed structured ANF. Add immutable *observation
metadata* for machine-generated functions and selected operation-completion
points; do not add a machine execution opcode or consult ASTs in an executor.
The verifier must validate observation IDs, referenced values and dominance.
The deep-copy owner, Core renderer, metadata emitter and both executors must
agree before these points become executable tracing support.

Observers must run after suspended calls or child blocks actually complete.
Observing a scheduling instruction as if it had completed would misreport
faulted candidates and is prohibited. Native hook storage belongs in explicit
continuation state, following ADR 0012. No borrowed slot can survive a frame
release through a trace record.

The implementation includes the bounded recorder, verified completion metadata,
interpreter/native hooks, serialization and replay. The CLI exposes opt-in
`--trace` capture and offline `replay`.

## Acceptance

Require traced/untraced output and fault equivalence; accepting, rejecting,
candidate/guard/reason/emission faults; nested steps; counter/capacity
boundaries; preview clipping; deterministic replay; allocation-failure paths
and ASan/UBSan for executor integration. Interpreter/native event parity must
compare source identity, dynamic order and visible values, with any
implementation-specific IDs normalized through the same verified metadata.
No language syntax or machine semantic change is authorized by this ADR.
