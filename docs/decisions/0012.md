# ADR 0012: Generated native call continuations and heap frames

Status: accepted for the C17 backend.

## Decision and scope

Resumable structured C functions execute against explicit heap frames.
Values remain immutable and acyclic, with checked reference counts, borrowed
inputs, owned results and iterative allocation-free destruction. See the
[runtime contract](../runtime.md).
There are no source language changes. A generated body is compiled C with
ordinary expressions, branches and resume points at calls. This dispatcher
does not consume AST, Core instructions or bytecode and is not an interpreter.

The original C signature remains the host entry facade:

```c
tf_status tf_f_17(tf_context *ctx,
                  const tf_value *captures, size_t capture_count,
                  const tf_value *args, size_t argc, tf_value *out);
```

Such a facade initializes a `tf_stack`, invokes `tf_stack_run`, then destroys
the dispatcher after observing its fault. Native generated bodies and builtin
callback adapters use `tf_stack_resume(tf_stack *, tf_stack_frame *)` internally.
They never invoke a facade, a generated resume, or a synchronous native call
adapter recursively. The dispatcher is the only caller of resume functions.
The runtime rejects nested facade/dispatcher entry in an active context.

The dispatcher is implemented in
runtime/include/ternfold_rt_stack.h and runtime/src/ternfold_rt_stack.c.
The native stack tests exercise its ownership and failure protocol.

## Frame protocol

Generated immutable tables declare the resume pointer, ordinary/entry/prelude
kind, parameter/result types and value slot count. Entry validates IDs, shapes,
capture/argument types, call kind and all allocation arithmetic before accessing
or retaining child values. Static source calls require ordinary functions;
closure calls permit ordinary or synthetic prelude functions, never entry-only
functions. A host entry-only target must be the table's designated entry.

A frame has a resume PC, stable pointers to slots and copied inputs, its parent,
the parent's destination slot and original invocation span. All value storage
starts as Unit. Every argument and capture is checked-retained into owned frame
storage, including inline scalar copies. Borrowed C-local argument arrays may
therefore expire as soon as the scheduling helper returns. The closure box
itself need not remain alive after its captures have been copied.

A resume performs one control action: `tf_stack_call`, `tf_stack_call_closure`
or `tf_stack_return`, then returns that helper's status. Releasing independent
local owners after scheduling is permitted; further fallible or language
operations are not. A call stores the continuation PC and pushes a child with
an empty parent result destination. The C resume returns before the dispatcher
invokes that child. On return, the dispatcher moves the validated result slot
to the parent, clears the source, frees the child, and resumes the parent.
Missing actions, repeated actions, bad result types and occupied destinations
produce R004 and unwind. This conservative discipline keeps other binding
owners live until frame exit; generated branch slots remain Unit if untaken.

No argument, capture, continuation or owned binding needed after suspension
may live only in a resume's C automatic storage. Persistent loop state belongs
in slots/PCs. Generated operands remain separately evaluated in Core order.

## Builtin map/fold adapter integration

`tf_stack_call_closure` is also the builtin callback request interface; no
additional synchronous callback ABI is needed. The native body table installs
map/fold adapters as ordinary helpers for direct calls and as
`TF_RT_PRELUDE_WRAPPER` entries for first-class closure calls:

1. On entry keep the input list, callback, index, accumulator or partial result
   owners in frame slots. Empty map returns its empty list; empty fold returns
   a retained initial accumulator without scheduling a callback.
2. Project the next element and prepare the callback arguments in ordered
   statements. Schedule one callback with `tf_stack_call_closure`, an empty
   result destination, and a continuation PC. Use the wrapper's `frame->span`
   as the callback invocation origin, including beyond 1024 calls; the legacy
   fixed-prefix `tf_invocation_span(ctx)` cannot provide that extended origin.
3. At that PC move the owned result into a single budgeted frame-owned map
   buffer, or replace the accumulator for fold, release obsolete owners, advance the
   index, and schedule the next callback. Return the final aggregate only after
   all callbacks succeed. Each callback may itself schedule recursive source
   calls or more builtin callbacks on this same dispatcher.

On success, map constructs its result list once. On a callback fault all
partial results stay private and are released by the frame's runtime-only
cleanup hook before slot teardown. Neither the dispatcher nor its adapters writes stdout
or publishes emissions. Entry's staged emissions and final returned output must
remain owned slots/aggregates until the whole host invocation succeeds.
The generated-code and native harness tests cover these adapters.

## Resource accounting, faults and cleanup

`tf_stack_init` does not allocate. The explicit call limit normally comes from
`ctx->config.call_limit` (default 1024); zero is valid. Larger dispatcher limits
are permitted without increasing the context's existing inline trace array.
The run preallocates a full `limit * sizeof(tf_call_frame)` trace, checking the
multiplication. This trace is retained for successful reuse until destroy.
It is charged to the context's existing live byte budget and allocator.

Each frame charges exactly the allocator request:

```text
sizeof(tf_stack_frame)
  + (body.slot_count + argc + capture_count) * sizeof(tf_value)
```

Both additions and the multiplication/header addition are checked before
allocation. Frame, trace and boxed value storage share `ctx->live_bytes` and
`ctx->config.byte_budget`; budget checks subtract only after proving the live
count is within budget. Allocator-private overhead is excluded. A too-small
trace/frame budget, allocator failure, retain overflow or exhausted call limit
returns R003 without a partial owned result. A failed child entry has no active
child trace entry, leaves the parent PC/destination unchanged, and releases any
partially retained argument/capture prefix. Successful call entry adds one
language frame; the failed over-limit attempt is not counted as entered.

Only the first context fault wins. Original operator/call spans survive helper
failure and protocol R004 faults. A resume's `TF_FAULT` without a recorded
context fault is a host capability failure, as in the numeric helper's unsupported
Float contract: preserve the absent language fault, return Unit, and unwind.
An unknown status or a successful resume with no control action is R004.
On a language fault the dispatcher freezes
the active full trace without allocation, then iteratively visits every frame
and every initialized slot/input. `tf_release` itself uses the existing intrusive,
allocation-free value destruction chain. Frame deallocation, return-slot moves
and unwind cannot fail or allocate. Successful return publishes the host output
only at the root's final move; any failure leaves Unit. Depth and active frame
state return to zero after every accepted run, including fault.

`tf_stack_fault` owns no extra allocation: its frame view borrows the dispatcher's
preallocated full trace until `tf_stack_destroy`. The unchanged context records
the same first code/span plus its first `min(depth, 1024)` frames in its own array.
That prefix remains valid after dispatcher destruction. A preexisting context
fault is returned unchanged without any allocation or body execution.

This split is explicit: for extended limits, a host must retain its dispatcher
until complete fault rendering, then destroy it. An original-signature facade
that destroys its local handle exposes only the context prefix; its normal
default limit is 1024, so that prefix is complete. Unifying dynamic trace lifetime
with context storage would require the context owner's separate ABI change.
Do not assign the context's fault pointer to dispatcher storage that will be freed.

## Verification

The strict and sanitizer suites exercise deep calls, callbacks, depth and byte
budgets, allocation failures, retain overflow, invalid frame actions, fault
origins and cleanup. The native generation tests also compare compiled programs
with the reference interpreter. Run them from the source root:

```powershell
./scripts/build.ps1 check -Compiler $cc
./scripts/build.ps1 sanitize -Compiler $cc
```

See [testing](../testing.md) for coverage and [installation](../installation.md)
for the verified Windows toolchain. Other compiler platforms and Windows
LeakSanitizer remain unverified.
