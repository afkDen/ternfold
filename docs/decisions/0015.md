# ADR 0015: Conservative verified Core optimization and release boundaries

Status: accepted for Ternfold 0.2.

## Decision

Expose explicit Core levels zero and one through `tf_core_optimize`. Zero is
the reference/default. Both levels borrow a verified handle during the call,
deep-copy its Core, and independently verify the result before publishing an
owning `TfCoreOptimization`. The result borrows only the stable source objects
in spans and its allocator context. Destroy its verified view before its Core
owner. There is no AST execution, frontend dependency, mutable global pass state,
or shared Core schema change. `emit-c` and `build` accept `--opt 0|1`; default
emission uses the original verified input directly at level zero.

Level one folds block-local, known inline scalar Unary/Binary operations only.
Int and Float arithmetic use the existing checked numerical helpers. Any
overflow, zero divisor, negative Int exponent, or unsupported Float capability
leaves the original operation executable. Int-to-Float conversion for real
division occurs separately for each operand. Float operations preserve finite
binary64, positive zero, per-operation rounding, underflow and reciprocal-first
power rules. Scalar comparisons use exact Int/Bool/Char/Unit comparisons or
finite canonical Float bit ordering; they do not evaluate host floating-point
expressions. Text and aggregate operations, builtins, calls, projections,
branches, maps, control flow and unknown operands are not folded.

Constant knowledge resets at each lexical block. A chain of safe scalar results
can fold within that block. Every original Let, ValueId, type, source span,
terminator, function/block ID and observation point remains in place. Existing
constant IDs remain valid; new scalar constants append in function/block/let
order with the original operation span. No dead-code elimination, hoisting,
inlining or graph simplification is authorized here. This Core has no redundant
copy opcode to remove.

For native releases, `tf_native_lifetimes` analyzes one verified function and
returns an owning plan containing only numeric IDs and boundary offsets. Only
single-block functions without If, SwitchTag, ListMap or builtin map/fold are
eligible. Unsupported functions return a successful, ineligible empty plan and
retain existing full-frame cleanup. Static/closure calls remain eligible because
the emitter must use their actual completion/resume boundary.

## Preservation arguments

| Transform | Argument | Counterexample evidence |
|---|---|---|
| Checked scalar folding | The same checked helper proves the original scalar result succeeds. Replacing only that operation with its scalar constant preserves type, bits and deterministic outcome. Dependencies and operation count remain fixed. | Int endpoints, IntMin negation and division/remainder by -1, zero divisors, negative exponent, powers at overflow, finite Float overflow/underflow/zero, mixed real division. |
| Local propagation | Only earlier known scalar definitions in the same lexical block are used. Faulting definitions never become known. No operand expression, branch or call is executed by the pass. | Short circuits containing faults, ordered candidate/guard/emission faults, record-field fault order, idempotence, caller Core unchanged and independently destroyed. |
| Observation preservation | Neither lets nor boundaries are removed or renumbered, so observation IDs and actual completion points remain identical. | Exact interpreter event/preview comparison and native opt0/opt1 trace/source-map byte comparison, malformed metadata rejection. |
| Last-use release | A value is retained through its definition, every operand use and every observation read. The returned value is excluded. Every later aggregate/closure/result already owns its retained children. Releases clear slots to Unit, so normal frame cleanup remains valid. | Shared embedded-NUL Text, captured closure result, returned list child, dead parameter, delayed observations, retain overflow and every native allocation failpoint. |
| Call continuation | Operands stay owned across suspension; the release boundary is after the child result arrives and completion observations run. A failed/suspended call cannot reach that boundary. Frame inputs remain separately owned by the runtime. | Handwritten structured resume harness uses the computed plan, checks live operands on resumption, and checks child-fault/retain-fault unwinding and Unit failure outputs. |

These transforms cannot hide lexical `next` dependencies: resolution, typing,
machine planning and verification precede optimization. A cycle in a constant
false branch still rejects with E404; duplicate writers still reject with E402.
No verified handle is produced for either error.

## Storage and failure reasoning

The optimizer mutates only its unpublished deep copy. The owner's arrays were
allocated without const qualification; casting its private const view back to
mutable storage does not modify the caller or a C object defined const. A
temporary constant descriptor table is bounded by original constants plus all
lets, with checked count sums and byte multiplication. Per-function known-value
storage checks `value_count + 1` and its byte size. Final copying and verification
complete before the public out pointer is assigned. Failure destroys scratch,
temporary constants, any final copy and any verified view exactly once. Inline
scalars carry no heap-child ownership. Faulting operations and their spans remain
unchanged; no execution or emission publication occurs in this pass.

Lifetime storage checks the slot increment, boundary additions and every array
multiplication. Verified definitions/operand/observation IDs bound all indexing.
Each defined, nonreturned value enters exactly one release bucket. Prefix sums
cannot exceed the number of defined values, itself bounded by value_count.
Offsets are filled/restored deterministically; IDs within a bucket ascend.
No runtime references are retained by a plan. On failure all plan storage is
destroyed and out stays NULL. Release itself is the existing iterative,
allocation-free runtime operation; fault exits retain the existing dispatcher
unwind. Counted test allocators assert no outstanding owners; native tests also
assert zero live bytes and no further allocation attempts during unwind.

R003 allocation counts/limits and interpreter work-budget coincidence are not
equivalence promises. Appended constants and scratch copies can increase compiler
or startup memory. Shorter native lifetimes may reduce live owners but do not
shrink the fixed frame slot allocation or separately owned frame input arrays.

## Emitter integration contract

1. Preserve opt0 as the reference/default; invoke the optimizer only after
   `tf_core_verify`, retaining source snapshots until the optimization owner dies.
2. Analyze the exact verified Core being emitted, once per function. Prepare
   plans before writing generated output so an allocation failure cannot publish
   partial output. Allocation failure is a host error; only ineligibility selects
   the documented full-frame cleanup fallback.
3. For an eligible function, query boundary `j` after all observations with
   `after_let == j`, before the next operation/return. At zero, parameter/capture
   slot retains and `tf_stack_trace_begin` must already have completed.
4. Emit `tf_release(&f->slots[id - 1]);` for each returned ID. The function
   result is absent from all buckets; leave `tf_stack_return`'s move unchanged.
5. For a call, boundary `j + 1` belongs after `cont_VALUE` on resumption, after
   the dispatcher installs the owned result and completion observations finish.
   Never emit these releases at call scheduling. No fallible operation follows
   a successfully scheduled control action.
6. Do not release runtime-owned argument/capture arrays or argument staging
   scratch using this plan. Keep ordinary fault cleanup for every slot, including
   slots already cleared to Unit. Keep branches/maps on existing cleanup paths.

## Affected layers and acceptance

Core transformation, backend analysis, CLI selection and production lifetime
emission are integrated. The interpreter and runtime are exercised as consumers.
Syntax, tokens, AST, types and machine planning retain their existing rules;
graph rejection tests enforce their earlier phase boundary.

See [testing](../testing.md) for the strict and sanitizer gates. The benchmark
script records compiler hashes, timings and sampled working set on one
workload. Those measurements do not establish a general performance gain.
