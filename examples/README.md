# Example corpus

The C17 reference interpreter and native compiler execute the maintained run
examples on the documented Windows host. `manifest.json` records the owning
phase, command, exact stdout (including escaped NUL), input and expected error
code. `run` cases execute; `check` cases test static acceptance or rejection;
`tokens` cases exercise the lexical demonstrations. Vocabulary and invalid
lexical streams are deliberately token fixtures rather than executable programs.
M12 checks that every example source has an active manifest case.

Start with `intro/hello.tfd`, then `intro/counter.tfd`. `features/snapshot_swap.tfd` distinguishes old-state reads from sequential assignment; `dependency_order.tfd` exposes the candidate graph. `guard_short_circuit.tfd` and `boundaries/candidate_fault.tfd` deliberately show different fault orders. `showcase/branching_inventory.tfd` combines modules, nominal data, scheduled proposals, rejection, delayed output, and branching from a retained snapshot.

The inventory starts at count 3 with capacity 10. Adding 4 gives count 7
and 3 free; adding 5 to that snapshot rejects and retains count 7. Taking
the original count 3 down a separate branch and adding 1 gives count 4 and
6 free. The exact transcript is in the manifest. Inspect the proposal order
with `plan examples/showcase/branching_inventory.tfd --root examples`.
`showcase/models/shelf.tfd` is a library root checked without main.
`invalid/` programs are expected to fail semantic checks.

[Checkout](showcase/checkout.md) composes stock and wallet machines with a pure
function. If the wallet rejects after the stock proposal succeeds, the helper
returns both original snapshots and discards the uncommitted stock emissions.
The example also folds over a sequence of orders and branches independently
from the original pair.

`course/precedence_bindings.tfd` makes arithmetic association, short circuiting,
immutable binding shadowing, dependency-ordered next writers and retained old
snapshots observable through an exact transcript.

The [classroom Symbol Table](../tests/fixtures/numerical/Symbol%20Table.txt)
is the checked two-column output for `course/operator_inventory.tfd`. To
regenerate it into an existing directory:

```powershell
./build/ternfold-lexer.exe examples/course/operator_inventory.tfd --classroom --output-dir build
```

The analyzer writes `build/Symbol Table.txt`. The canonical C01 test compares
the generated bytes to the maintained sample and checks the full operator
inventory. This private compiler sample is separate from the public lexical ZIP.

From the project directory, in one PowerShell session:

```powershell
./scripts/build.ps1 build
./build/ternfold.exe run examples/showcase/branching_inventory.tfd
./build/ternfold.exe build examples/showcase/branching_inventory.tfd -o build/inventory.exe --cc $env:TF_CC
./build/inventory.exe
```

For captured input, use `run examples/course/main_io.tfd --stdin-file FILE`
with a UTF-8 file; the generated executable accepts the same input-file option.
Building native programs requires the configured C17 toolchain. Running a normal
generated executable does not require the compiler or these source directories.
